# FAZA 4 — QOLGAN MODULLAR

> **Mo'ljal:** 2–3 sessiya · **Xavf:** 🟡 O'RTA

Faza 3 dan keyin eng qiyin qism ortda qoladi. Bu fazada qolgan bo'limlar
saytga ko'chiriladi. Ularning ko'pi **o'qish** — shuning uchun tezroq boradi.

## 4.1 Boss dashboard (rahbariyat)

`apiBossData()` allaqachon ishlatilyapti. Endi **chuqurlashtirish**:

- Obyekt qatoriga bosilsa → yon panel (drawer) ochiladi, ichida:
  ЧЕЛ / МАШ / МАТ / ОБ / КАБ bo'yicha taqsimot
- `subItems` bor obyekt — **guruh** (shartnoma). Yig'ilib/ochilsin
- Shartnoma bo'yicha: `dogSumma`, `tolangan`, `avans`, `debitor`

**Diagramma qoidasi** (`06_DIZAYN_TIZIMI.md` §8):
- Obyektlar taqqoslash → **gorizontal ustun** (nomlar uzun)
- ЧЕЛ/МАШ/МАТ/ОБ taqsimoti → **stacked bar**, pirog EMAS
- `oylar` massivi hozir **bo'sh** → **vaqt grafigi yo'q**. Bo'sh ma'lumotdan
  grafik yasamang

## 4.2 Shartnoma

```ts
apiShartnomaOl()                       // ro'yxat
apiShartnomaSaqla(d)                   // saqlash
apiShartnomaOchir(no)                  // o'chirish
apiShartnomaBogOl()                    // obyekt ↔ shartnoma bog'lanishi
apiShartnomaBogSaqla(obyekt, shartnomaNo)
apiShartnomaDashboard()                // jamlanma
```

**⚠️ Накрутка mantiqi.** Smeta summasi — «toza narx». Buxgalteriyaga
o'tganda накрутка qo'shiladi. Bu hisob **GAS'da** (`80_Shartnoma.js`),
saytda **qayta hisoblanmaydi**. `apiShartnomaDashboard()` bergan raqamni
ko'rsating, ustiga koeffitsient ko'paytirmang.

O'chirish — **doim tasdiq modali** bilan, shartnoma raqami va summasi ko'rsatilib.

## 4.3 Buxgalteriya

`85_Buxgalteriya.js` dagi `api*` funksiyalar. Ro'yxatni
`apiWebApiFunksiyalar()` dan oling — nomlarni taxmin qilmang.

## 4.4 Sklad

```ts
apiSkladOl(qidiruv)   // qidiruv bo'yicha
```

- Qidiruv maydoni **debounce 300ms** bilan
- Natijalar jadvalda, qoldiq miqdori bo'yicha rang: 0 → `--danger`,
  kam → `--warn`, yetarli → `--text`

## 4.5 Monitoring / diagnostika

`apiWebApiLog()` — oxirgi 50 API chaqiruvi. Kichik sahifa:
funksiya nomi, holat, vaqt (ms). Sekin chaqiruvlar (>5000 ms) `--warn` bilan.

# FAZA 5 — DIZAYN SAYQALI

> **Mo'ljal:** 2 sessiya · **Xavf:** 🟢 PAST
> **Bu foydalanuvchi uchun eng muhim faza.** Uning asl shikoyati aynan shu edi.

Bu fazada **yangi funksiya qo'shilmaydi**. Faqat mavjudi sayqallanadi.

## 5.1 To'liq dizayn auditi

`06_DIZAYN_TIZIMI.md` §12 tekshiruv ro'yxatini **har sahifa uchun alohida**
o'tkazing. Topilgan har nomuvofiqlikni tuzating.

Ayniqsa:
- Har pul/hajm katagida `.num` bormi?
- Oraliqlar 4px setkadami?
- Har tugma 36px balandlikdami?
- Har ro'yxatda 3 ta holat (yuklanmoqda/bo'sh/xato) bormi?

## 5.2 Klaviatura

| Tugma | Harakat |
|---|---|
| `Ctrl/⌘ + K` | global qidiruv (barcha obyekt va ish turlari) |
| `Ctrl/⌘ + S` | tahrir rejimida saqlash |
| `Esc` | modal yopish / tahrirni bekor qilish |
| `←` `→` | daraxtda yopish / ochish |
| `↑` `↓` | daraxtda yurish |
| `?` | tugmalar ro'yxati modali |

## 5.3 Yorug' rejim

Endi qo'shiladi (avval emas — chala qilingandan ko'ra umuman qilmagan yaxshi).

⚠️ **Avtomatik teskari aylantirmang.** Har rang yorug' fon uchun **alohida**
tanlanadi va tekshiriladi. `--t-bl/rs/mat/ob` uchun yorug' rejim qiymatlari
`06_DIZAYN_TIZIMI.md` §2.3 dagi kabi tasdiqlangan bo'lishi kerak.

## 5.4 Mobil

- Sidebar → pastdagi tab bar
- Jadval → karta ro'yxati
- Modal → bottom sheet
- Bosiladigan maydon ≥ 44px
- **375px kenglikda gorizontal skroll bo'lmasin**

## 5.5 Tezlik hissi

- Marshrut bo'yicha kod bo'linishi (`React.lazy`) — birinchi yuklash yengil
- Sahifaga kirishdan oldin ma'lumotni oldindan so'rash (prefetch on hover)
- `sessionStorage` kesh: `apiPapkaSkan` va `apiBossData` uchun
- Bundle hajmi **< 350 KB** (gzip < 110 KB)

## 5.6 Sayqal detallari

- Sahifa almashishida `260ms` fade + 8px yuqoriga
- Skeleton → tarkib o'tishi `200ms` fade (keskin almashmasin)
- Toastlar bir-birining ustiga taxlanadi, itarmaydi
- Uzun jadvalda skroll qilganda sarlavha «yopishib» qoladi
- Fokus halqasi har joyda ko'rinadi

# FAZA 6 — TEZLIK (Supabase o'qish qatlami)

> **Mo'ljal:** 2 sessiya · **Xavf:** 🟡 O'RTA
> **Bu fazani faqat 1–5 tugagach boshlang.**

## 6.1 Muammo

GAS chaqiruvi tez bo'lolmaydi:

| Chaqiruv | Vaqt |
|---|---|
| `apiWebApiSalom` | 20 ms |
| `apiPapkaSkan` | 5 s |
| `apiBossData` | 10–14 s |
| `apiHolatOl` (katta obyekt) | 15–30 s |

Skeleton va kesh buni **yengil qiladi**, lekin yo'qotmaydi.

## 6.2 Yechim — o'qish uchun alohida qatlam

```
YOZISH:  Sayt → GAS → Google Sheets     (haqiqat manbai, o'zgarmaydi)
                        ↓ sinxronizatsiya
O'QISH:  Sayt → Supabase (Postgres)     (100-200 ms)
```

`70_Supabase.js` allaqachon qisman qurilgan.

## 6.3 Qat'iy qoidalar

1. **Google Sheets — yagona haqiqat manbai.** Supabase — faqat nusxa
2. **Yozish HECH QACHON Supabase'ga bormaydi.** Faqat GAS orqali
3. Har yozuvdan keyin tegishli obyekt sinxronlansin
4. Ma'lumot eskirgan bo'lsa — foydalanuvchiga ayting:
   «Маълумот 4 дақиқа олдинги · [янгилаш]»
5. Supabase ishlamasa — **avtomatik GAS'ga qaytsin** (fallback), sayt
   sekinlashsin, lekin **o'lmasin**

## 6.4 Narx

Supabase tekin tarifi: 500 MB baza, 2 GB trafik/oy. Bizga yetarli.

⚠️ **Diqqat:** tekin tarifda loyiha **1 hafta faoliyatsizlikdan keyin
to'xtatiladi**. Kunlik ishlatilsa muammo yo'q.

## Faza 6 qabul mezonlari
